# hb/__main__.py - 代码映射

## 1. 职责

**`hb/__main__.py`** 作为 HarmonyOS 构建系统 CLI (`hb`) 的**入口点引导程序**。其主要职责包括：

- **工作空间验证**：通过向上遍历检测当前工作目录是否位于有效的 HarmonyOS 源代码树中，以定位 `build/hb/resources/global_var.py`。
- **动态模块加载**：使用 Python 的 `importlib` 动态加载并执行位于 `<ohos_root>/build/hb/main.py` 的实际 `main.py` 模块。
- **上下文切换**：通过以下方式在包级入口点 (`python -m hb`) 和项目特定的构建逻辑之间建立桥梁：
  - 计算从当前目录到 OHOS 根目录的相对路径
  - 将正确的 `main.py` 位置注入到 Python 模块命名空间中
- **错误处理**：在 OHOS 源代码目录之外被调用时引发描述性异常。

> **注意**：此文件是**CLI 外观模式**，将所有实际构建逻辑委托给 `main.py`。它使 `hb` 既可以是独立的 Python 包，又能在 OHOS 源代码树中具有上下文感知能力。

## 2. 设计模式

### 2.1 外观模式
`__main__.py` 作为 `main.py` 中复杂子系统的简化接口。它抽象了：
- 模块路径解析
- 动态加载机制
- 工作空间上下文检测

### 2.2 动态模块加载 (Importlib 模式)
```python
spec = importlib.util.spec_from_file_location('main', entry_path)
api = importlib.util.module_from_spec(spec)
spec.loader.exec_module(api)
```
使用 `importlib.util` 进行程序化模块加载，避免在 OHOS 树上下文之外会失败的硬编码导入。

### 2.3 目录遍历 (路径解析模式)
```python
cur_dir = os.getcwd()
while cur_dir != "/":
    global_var = os.path.join(cur_dir, 'build', 'hb', 'resources', 'global_var.py')
    if os.path.exists(global_var):
        return True, cur_dir
    cur_dir = os.path.dirname(cur_dir)
```
实现**向上目录遍历**以发现 OHOS 根目录，使 `hb` 能够从项目内的任何子目录工作。

### 2.4 单例式入口点
`main()` 函数实例化 `Main` 类（来自 `main.py`）并调用其 `main()` 方法，有效地委托给单例协调器。

### 4.3 项目结构上下文

```
<ohos_root>/
├── build/
│   └── hb/                          # hb 包根目录
│       ├── __main__.py              # ← 入口点 (此文件)
│       ├── main.py                  # ← 核心逻辑 (委托至此)

```

## 6. 使用模式

### 6.1 有效使用 (在 OHOS 树内)
```bash
cd /path/to/ohos/
python -m hb build --product <product_name>
# 或
hb build --product <product_name>
```

### 6.2 无效使用 (在 OHOS 树外)
```bash
cd /tmp
python -m hb build
# 引发: [OHOS_ERROR]: 请在 ohos 源代码目录内调用 hb 工具
```

## 7. 架构说明

- **有意解耦**：此文件有意包含最少的逻辑，以避免当 `hb` 作为独立包安装但在 OHOS 上下文之外执行时出现导入错误。
- **上下文注入**：通过使用正确的 OHOS 根上下文动态加载 `main.py`，构建系统可以从任何子目录正确解析相对路径。
- **入口点约定**：`if __name__ == "__main__": sys.exit(main())` 模式确保退出码正确传播到 shell。
